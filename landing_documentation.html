01 // MULTIMODAL SYSTEM PIPELINE

MULTIMODAL FUSION & DUAL-LOOP ARCHITECTURE

Per Section 4 & 5 of the specification: cyclones are not treated as a 3rd image class. Instead, three distinct sensor streams fuse into an edge threat engine, separating the rapid onboard safety loop from blockchain latency.

BRANCH 1: SAR RADAR Iceberg Classification
X_SAR = [HH, HV, Avg]
P_I = P(iceberg | X_SAR)

PyTorch CNN models extract specular backscatter and depolarization across 75×75 C-band tiles to output calibrated iceberg probabilities.

BRANCH 2: WEATHER Cyclone Sequence Track
C_t = [Lat, Lon, Wind, Pres]
C_hat_(t+1:t+H) = f(C_(t-k:t))

Meteorological observation history feeds sequence models (LSTM / Transformer) to forecast cyclone track evolution and gale radii.

BRANCH 3: NAVIGATION Ship Kinematics
S_t = [Lat, Lon, SOG, COG, Heading, time_t]

Streaming GNSS/AIS telemetry replayed continuously to maintain dead-reckoning trajectory and course over ground.

BRANCH 4: FUSION ENGINE Threat Assessment & Routing
R_total = α·R_I + β·R_C + γ·R_cyb
Route* = argmin Cost(e)

Calculates Haversine CPA/TCPA, issues immediate bridge alerts, and dynamically bends Great-Circle routes via spherical A*.

KEY DESIGN DECISION: DECOUPLED DUAL-LOOP ARCHITECTURE (SECTION 5 & 14)

Fast Onboard Safety Loop (<18 ms): Sensors → Edge AI → Threat Engine → Local Bridge Alert & Dynamic Safe Route. Runs locally with zero dependency on network connection or blockchain mining delays.
Trusted Communication Loop: Threat Result → HAPS/Satellite → Proof-of-Authentication (PoAh) → MarineChain Ledger → Maritime Fleet Control Station. Authenticates, records, and provides immutable audit trails.

MATHEMATICAL FORMULATIONS (SECTIONS 9 & 10)
• Haversine Distance: d = 2R · arcsin( √( sin²(Δφ/2) + cos(φ_s)·cos(φ_h)·sin²(Δλ/2) ) )

04 // DYNAMIC PATH OPTIMIZATION

A* DYNAMIC WEATHER ROUTE PLANNING

Per Section 11 of the specification: Graph optimization $G = (V, E)$ dynamically recalculating paths whenever hazard forecasts materially change.

GRAPH OPTIMIZATION COST FUNCTION (SECTION 11)
Cost(e) = α·Distance(e) + β·IcebergRisk(e) + γ·CycloneRisk(e) + δ·WeatherRisk(e)
Route* = argmin_R ∑_{e ∈ R} Cost(e)

SPHERICAL GREAT-CIRCLE RECALCULATION

Initial nominal tracks are projected as spherical geodesics. Waypoints are evaluated every 30 NM along the transatlantic corridor against moving cyclone gale envelopes.

+45 NM SAFETY CLEARANCE BUFFER

Whenever the predicted distance $D_h < R_{\text{gale}} + 45\text{ NM}$, the cost penalty increases exponentially, deflecting the vessel northwards while preserving fuel efficiency.

DRIFTING ICEBERG AVOIDANCE

Iceberg state vectors $I_t = [\text{Lat}_i, \text{Lon}_i, V_i, \theta_i]$ predict southward Labrador Current drift, guaranteeing minimum passing distances above 18 NM.

05 // CYBER-RESILIENT BLOCKCHAIN

MARINECHAIN / POAH & HAZARD MESSAGE SCHEMA

Implementing Section 2, 14 & 15: ML-assisted trust score calculation ($TS_i^{ML}$), Proof-of-Authentication (PoAh) consensus, and standardized hazard message transmission.

ML-ASSISTED TRUST SCORE (SECTION 2.3)
TS_i = VB_i + ST_i - MV_i
p_i = P(malicious | x_i)
TS_i^ML = α·TS_i + (1 - α)·(1 - p_i)

The ML probability supplements, rather than replaces, the deterministic PoAh trust logic, preventing adversarial takeover while filtering compromised sensor nodes.

          SECTION 19: IMPORTANT EXPERIMENTAL CAUTIONS & RIGOR GUIDELINES
        

        
    
          
  • The Statoil/C-CORE dataset is a satellite SAR ship-vs-iceberg classification dataset; it is not a live onboard radar stream.
    • 
          
  • Cyclone prediction requires separate meteorological tracking datasets; synthetic encounters are labelled as simulations.
    • 
          
  • Do not claim real-world safety performance from simulated threat thresholds; thresholds are explicitly experimental.
    • 
          
  • Do not select a model only by accuracy; inspect precision, recall, F1, ROC-AUC, calibration/log loss, and class balance.
    • 
          
  • Keep the immediate onboard warning loop independent of blockchain consensus latency (<18 ms local response).
    • 
          
  • Report inference latency and update rates if claiming real-time operational capability.
